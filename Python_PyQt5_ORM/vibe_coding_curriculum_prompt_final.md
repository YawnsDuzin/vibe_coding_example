# 바이브코딩 교육 커리큘럼 설계 프롬프트 (최종본)

---

## 역할
당신은 **비개발자를 위한 바이브코딩(AI 페어 프로그래밍) 교육 커리큘럼 설계 전문가**입니다. 교육공학·개발자 온보딩·성인 학습 이론에 모두 익숙하며, "AI 시대의 비개발자"가 실제로 쓸 수 있는 소프트웨어를 만들도록 이끄는 설계를 해야 합니다.

---

## 0. 바이브코딩 철학 (이 커리큘럼의 헌법)

바이브코딩은 "AI에게 코드를 맡기는 것"이 아니라 **"AI와 협업하여 학습자가 의도·설계·검증에 집중하는 것"**입니다. 커리큘럼 전반에 아래 원칙이 관통해야 합니다.

### Claude Code-First 원칙

이 커리큘럼에서 Claude Code는 **코드 작성 도구에 한정되지 않습니다.** 파이썬 문법 학습, SQL/ORM 실습, 설정 파일 작성, 요구사항 문서 작성, ERD 설계, 디버깅, 테스트 등 **모든 학습 활동의 주 작업 환경**이 Claude Code입니다. 학습자는 처음부터 끝까지 Claude Code 안에서 작업하는 습관을 형성해야 합니다.

이를 위해 각 단원은 다음을 반드시 포함합니다:
- **프롬프트 레시피**: 해당 단원의 작업을 Claude Code에서 수행할 때 사용하는 구체적인 프롬프트 예시
- **커스텀 Skills**: 반복되는 작업 패턴이 있을 경우, 이를 Claude Code 커스텀 Skill로 제작하여 재사용

| 구분 | AI(Claude Code)가 맡는 것 | 학습자가 반드시 책임지는 것 |
|---|---|---|
| 의도 | (도움만) | **"무엇을 왜 만드는가"** 정의 |
| 설계 | 후보안 제시, 문서 초안 생성 | **선택과 트레이드오프 판단** |
| 구현 | 코드 생성 | 결과물이 의도대로인지 **읽고 검증** |
| 문서화 | PRD·ERD·설정 파일 초안 작성 | **내용 검토·수정·확정** |
| 학습 | 개념 설명, 예제 생성, 코드 해석 | **이해 확인·질문·반복 연습** |
| 디버깅 | 가설 제시 | **재현 조건·증거 수집** |
| 배포 | 스크립트 제공 | **내 환경에서 동작 확인** |

이 표는 각 단원의 실습 설계에 **반드시 반영**되어야 하며, 학습자가 "AI에게 던지고 기다리는" 수동적 패턴으로 빠지지 않도록 하는 장치가 단원마다 있어야 합니다.

### 학습 깊이 원칙: 구문 작성이 아닌 구조 이해

비개발자가 바이브코딩을 할 때 파이썬 문법, SQL 쿼리, Git 명령어의 **구문(syntax)을 외워서 직접 작성할 필요는 없습니다.** 그러나 **전체적인 틀과 작동 방식에 대한 이해("느낌")는 반드시 있어야** Claude Code가 알아듣기 쉬운 프롬프트를 작성할 수 있고, AI가 생성한 결과물을 검증할 수 있습니다.

이 원칙이 각 영역에서 의미하는 구체적 기준:

| 영역 | 몰라도 되는 것 (구문) | 반드시 알아야 하는 것 (틀) |
|---|---|---|
| Python | `for i in range(len(items)):` 구문 작성 | 함수·클래스·모듈이 뭔지, 데이터가 코드 안에서 어떻게 흐르는지 |
| SQL | `SELECT u.name FROM users u JOIN roles r ON ...` 작성 | 테이블·컬럼·관계(1:N, N:M), CRUD의 개념 |
| Git | `git rebase -i HEAD~3` 명령어 | 커밋·브랜치·되돌리기의 개념 ("저장 지점"이라는 비유) |
| 아키텍처 | 디자인 패턴 이론 | UI → Service → Repository → Model 계층이 왜 나뉘어 있는지 |

**이 차이가 프롬프트 품질에 직접 영향을 줍니다:**

| 틀을 모르는 학습자 | 틀을 아는 학습자 |
|---|---|
| "할 일 목록 기능 만들어줘" | "Task 모델을 만들고, Repository에 CRUD를 추가하고, Service에서 완료 상태 변경 로직을 작성해줘" |
| "안 돼, 고쳐줘" | "저장 버튼 클릭 시 DB에 반영이 안 되는데, Service에서 session.commit()이 빠진 것 같아" |
| "데이터 저장하게 해줘" | "User 테이블에 email 컬럼을 추가하고 Alembic 마이그레이션을 생성해줘" |

따라서 커리큘럼의 각 기술 단원(Python, SQL, Git 등)은 **"이 기술을 직접 구사하는 사람"이 아니라 "이 기술의 구조를 이해하고 AI에게 정확히 지시할 수 있는 사람"**을 목표 수준으로 설정합니다. 단, **검증 능력**은 필수입니다 — 코드를 읽었을 때 대략 무슨 일이 일어나는지 추적할 수 있어야 "AI가 잘못 만든 것"을 알아챌 수 있습니다.

## 1. 목표

비개발자가 자신의 업무 요구사항을 **직접 설계 → AI와 구현 → 검증 → 배포**까지 수행할 수 있도록 하는 실전 커리큘럼을 설계하세요. 최종 산출물은 "학습 종료 시점에 자기 업무에 쓸 수 있는 데스크톱 앱 1개를 가지고 나가는 것"입니다.

**핵심**: 이 모든 과정 — 문법 학습, SQL 실습, 요구사항 문서 작성, 설정, 코드 구현, 디버깅, 배포 — 을 **VSCode + Claude Code Extension 환경**에서 수행합니다. 학습자는 VSCode에 Claude Code Extension을 설치한 통합 환경을 유일한 작업 도구로 사용하며, 각 작업에 맞는 프롬프트와 커스텀 Skills를 익혀 나갑니다.

## 2. 대상 학습자 페르소나

- **주 페르소나**: 코딩 경험이 거의 없는 기획자·PM·디자이너·현업 실무자
- **특징**:
  - 업무 자동화나 사내 데스크톱 도구를 **직접** 만들고 싶어함
  - AI 도구 사용 경험은 있으나(ChatGPT, Claude 웹 등), 터미널·Git·가상환경 같은 개발 환경 용어에 낯섦
  - 논리적 사고·문서화 역량은 있음 (이걸 레버리지 해야 함)
- **시작 시점 선수 지식 체크리스트** (설계에 포함 요망):
  - 파일 탐색기에서 경로 개념 이해 여부
  - 엑셀 함수 사용 경험
  - 간단한 SQL 경험 (있으면 가속, 없으면 허용)

## 4. 스택에서 파생되는 설계 원칙 (반드시 커리큘럼에 반영)

1. **DB 독립성**: 처음부터 ORM 계층을 거치게 설계하여, SQLite → PostgreSQL 전환 시 비즈니스 로직이 변하지 않음을 **체감**시킬 것
2. **UI-로직 분리**: PyQt5 시그널/슬롯을 통해 UI 이벤트와 비즈니스 로직을 분리하는 패턴을 **초반부터** 도입 (나중에 리팩토링하면 늦음)
3. **환경 재현성**: venv + requirements.txt + .env를 "선택"이 아닌 **"기본 습관"**으로 가르칠 것
4. **검증 가능성**: AI가 생성한 코드를 학습자가 **읽고 실행하고 확인**하는 루틴을 모든 실습에 삽입
5. **롤백 가능성**: Git 커밋 단위를 "내 손으로 되돌릴 수 있는 최소 단위"로 훈련
6. **보안 최소선**: 비밀번호 평문 저장 금지, 시크릿은 .env, DB 바인딩 변수 사용(문자열 직접 결합 금지) — 보일러플레이트에서 예시로 제공
7. **Claude Code 전 과정 활용**: 코드 작성뿐 아니라 파이썬 문법 학습, SQL 쿼리 실습, 요구사항 문서 작성, 설정 파일 생성, ERD 설계, 디버깅 등 **모든 작업을 Claude Code를 통해 수행**. 각 작업에 사용하는 프롬프트를 문서화하고, 반복 패턴은 커스텀 Skill로 제작하여 재사용

## 5. 보일러플레이트 스펙 (교육용 표준 템플릿)

모든 실습과 캡스톤은 **아래 보일러플레이트에서 출발**합니다. 커리큘럼은 보일러플레이트를 "읽고, 설명하고, 확장"하는 방식으로 진행됩니다 (백지에서 시작하지 않음 — 비개발자 학습 곡선 완화의 핵심 장치).

### 5.1 UI 기본 구조
- **메인 폼**: 좌측 Navbar 형식 (expand/collapse 가능), 기본 폼 1개 구현, 멀티 폼 확장 가능한 구조
- **라이트/다크 테마** 토글 (표준 QSS 스타일시트로 구현)

### 5.2 인증 시스템
- 로그인 / 회원가입 화면
- **사용자 3단계 등급** (예: admin / manager / user) 권한 분기
- 비밀번호는 해싱 저장 (bcrypt 또는 passlib)
- 세션/현재 사용자 상태 관리

### 5.3 데이터 계층
- SQLAlchemy ORM 모델 예시 (User, Role, 기본 엔티티 1개)
- Alembic 마이그레이션 초기 설정
- DB 연결 팩토리 (`.env`에서 SQLite/PostgreSQL 선택 가능)

### 5.4 설정 관리
- `.env` 기본 설정 (DB 종류, DB 접속 정보, 프로그램명, 로그 레벨)
- `python-dotenv`로 로드

### 5.5 표준 스타일 · 공통 컴포넌트
- 라벨·버튼·입력폼·그룹박스·체크박스 표준 스타일
- 커스텀 컨트롤러:
  - 토스트 알림 (상단 슬라이드)
  - 모달 다이얼로그 (확인/취소)
  - 로딩 스피너

### 5.6 인프라
- 로깅 설정 (파일 + 콘솔, 일자별 롤링)
- 예외 처리 데코레이터(혹은 유틸)
- 프로젝트 구조 (계층 분리가 눈에 보이는 디렉토리 구조)
  ```
  app/
    ui/           # PyQt 위젯·폼
    services/     # 비즈니스 로직
    repositories/ # ORM 쿼리
    models/       # SQLAlchemy 모델
    core/         # 설정·로깅·인증
    resources/    # .ui, .qss, 아이콘
  ```

### 5.7 Claude Code 사전 설정
보일러플레이트에 아래 Claude Code 설정을 미리 포함하여, 학습자가 별도 설정 없이 바로 사용할 수 있도록 합니다:
- **`CLAUDE.md`**: 프로젝트 컨텍스트, 기술 스택, 코딩 컨벤션, 계층 구조 규칙 기술
- **프롬프트 자동 로깅 hook**: `UserPromptSubmit` hook으로 모든 프롬프트를 `.claude/prompt-log.jsonl`에 자동 저장
  ```
  .claude/
    settings.json          # hook 설정 포함
    hooks/
      log-prompts.sh       # 프롬프트 로깅 스크립트
    prompt-log.jsonl       # 자동 생성되는 프롬프트 로그 (gitignore 대상)
    skills/                # 커스텀 Skill 정의 디렉토리
  ```
- **기본 커스텀 Skills**: `/init-project`, `/explain-code` 등 교육 초반에 바로 사용할 Skill을 미리 제공
- `.gitignore`에 `.claude/prompt-log.jsonl` 추가 (민감 정보 보호)

## 6. 커리큘럼에 반드시 포함할 주제

아래 주제를 **가장 효과적인 순서와 분량**으로 재구성하여 제안하세요. 순서 변경·분할·통합·추가·삭제 모두 자유이며, **변경 시 근거를 함께** 적으세요.

1. **기초 IT 지식**: 파일시스템, 터미널, Git(커밋/브랜치/되돌리기), 가상환경·패키지 관리
   - **Claude Code 활용**: 터미널 명령어를 Claude Code에서 직접 실행하며 학습, Git 작업도 Claude Code를 통해 수행
   - **프롬프트 예시**: "현재 프로젝트의 파일 구조를 설명해줘", "venv를 만들고 requirements.txt에서 패키지를 설치해줘"
   - **커스텀 Skill 후보**: `/init-project` (venv 생성 → 패키지 설치 → Git 초기화 → .env 템플릿 생성을 한 번에 수행)

2. **Python 기본 문법**: 비개발자가 **"코드를 읽고 검증"**할 수 있는 수준 (작성보다 읽기에 비중)
   - **Claude Code 활용**: 코드 읽기 연습을 Claude Code와 대화하며 진행 — 코드 조각을 보여주고 "이 코드가 무엇을 하는지 설명해줘", 학습자가 이해한 내용을 Claude Code에게 확인
   - **프롬프트 예시**: "이 함수가 하는 일을 비개발자가 이해할 수 있게 한 줄씩 설명해줘", "for 루프와 리스트 컴프리헨션의 차이를 예제로 보여줘"
   - **커스텀 Skill 후보**: `/explain-code` (선택한 코드 블록에 대해 비개발자 눈높이로 줄별 해설 생성)

3. **데이터 모델링과 SQL 기초**: ERD → 테이블 스키마 변환, SQLite로 실습
   - **Claude Code 활용**: 업무 요구사항을 자연어로 설명하면 Claude Code가 ERD 초안과 SQL DDL을 생성, 학습자가 검토·수정
   - **프롬프트 예시**: "할 일 관리 앱에 필요한 테이블을 ERD로 설계해줘", "이 ERD를 SQLite CREATE TABLE 문으로 변환해줘"
   - **커스텀 Skill 후보**: `/generate-erd` (자연어 요구사항 → Mermaid ERD 다이어그램 + DDL 생성)

4. **ORM 계층**: SQLAlchemy 모델·세션·쿼리, Alembic 마이그레이션, "DB 교체 가능한 코드" 체득
   - **Claude Code 활용**: SQL DDL을 SQLAlchemy 모델로 변환하는 과정을 Claude Code가 수행, 학습자는 ORM 코드와 원본 SQL을 비교하며 이해
   - **프롬프트 예시**: "이 CREATE TABLE 문을 SQLAlchemy 모델로 변환해줘", "Alembic 마이그레이션 파일을 생성해줘"
   - **커스텀 Skill 후보**: `/create-model` (테이블 스키마 → SQLAlchemy 모델 + Repository 클래스 + Alembic 마이그레이션 스캐폴딩)

5. **PyQt5 기초**: 위젯·레이아웃·**시그널/슬롯**, Qt Designer로 와이어프레임 → 실제 UI
   - **Claude Code 활용**: Qt Designer로 만든 .ui 파일을 Claude Code가 Python 코드로 변환, 시그널/슬롯 연결 코드 생성
   - **프롬프트 예시**: "이 .ui 파일에 시그널/슬롯을 연결하는 코드를 작성해줘", "이 폼에 입력 검증 로직을 추가해줘"
   - **커스텀 Skill 후보**: `/create-form` (폼 이름 + 필드 목록 → PyQt5 위젯 클래스 + 시그널/슬롯 + Service 연결 스캐폴딩)

6. **요구사항 → 바이브코딩 가능한 설계**
   - PRD, ERD, UI 와이어프레임, To-do 분해
   - **아키텍처 결정**: UI / Service / Repository / Model 계층 분리
   - **Claude Code 활용**: 요구사항을 자연어로 Claude Code에 전달하면 PRD 초안, ERD, 아키텍처 구조, 작업 분해(To-do)를 생성 — 학습자가 검토·수정·확정
   - **프롬프트 예시**: "이 기능 요구사항을 PRD 형식으로 정리해줘", "이 PRD를 기반으로 UI/Service/Repository/Model 계층으로 작업을 분해해줘"
   - **커스텀 Skill 후보**: `/plan-feature` (기능 설명 → PRD + ERD + 계층별 To-do 분해를 한 번에 생성)

7. **Claude Code 환경**
   - `claude.md` 작성법 (프로젝트 컨텍스트, 코딩 컨벤션, 금지사항, 의사결정 로그)
   - Skills (기본 제공 Skill 활용 + 프로젝트 맞춤 커스텀 Skill 제작)
   - **프롬프트 자동 로깅 & Skill 추천 워크플로**:
     - `UserPromptSubmit` hook을 설정하여 모든 프롬프트를 `.claude/prompt-log.jsonl`에 자동 저장
     - 축적된 프롬프트 로그를 주기적으로 Claude Code에 전달하여 반복 패턴 분석 → Skill 후보 추천
     - 추천받은 패턴을 `.claude/skills/<name>/SKILL.md`로 제작·등록
     - 이 과정 자체가 "자신의 작업 패턴을 메타인지하는 훈련"이 됨
   - **Claude Code 활용**: Claude Code로 claude.md 자체를 작성·관리하고, hook 설정, 커스텀 Skill을 제작·테스트
   - **프롬프트 예시**: "이 프로젝트에 맞는 claude.md를 생성해줘", "자주 쓰는 이 작업 패턴을 커스텀 Skill로 만들어줘", "이 프롬프트 로그를 분석해서 반복되는 패턴을 찾고 Skill로 만들 만한 것을 추천해줘"
   - **이 단원에서 제작하는 Skills**: 이전 단원에서 소개한 Skill 후보들을 실제로 제작·등록·테스트
   - **커스텀 Skill 후보**: `/analyze-prompts` (`.claude/prompt-log.jsonl`에서 반복 패턴 분석 → Skill 후보 목록 + SKILL.md 초안 생성)

8. **AI와 함께하는 개발·디버깅**
   - 프롬프팅 전략 (맥락 제공·제약 명시·검증 요청)
   - **에러 메시지 읽는 법** (Traceback 해부)
   - 재현 가능한 버그 리포트 작성
   - GUI 특유의 디버깅 (이벤트 루프, DB 락, 위젯 생명주기)
   - **Claude Code 활용**: 에러 발생 시 Traceback을 Claude Code에 전달하여 원인 분석, 재현 조건 정리, 수정 코드 생성까지 Claude Code 안에서 수행
   - **프롬프트 예시**: "이 에러 Traceback을 분석하고 원인과 수정 방법을 알려줘", "이 버그의 재현 조건을 정리해줘"
   - **커스텀 Skill 후보**: `/debug` (에러 로그 수집 → 원인 분석 → 수정 제안 → 테스트 실행까지 단계별 가이드)

9. **AI 산출물 검증** ★ (바이브코딩 특화 — 별도 승격)
   - AI가 준 코드를 **읽고 의심하고 확인**하는 루틴
   - 최소한의 테스트 작성 (pytest 기본 1~2 패턴)
   - "AI가 모르는 것"을 알아차리는 신호들
   - **Claude Code 활용**: Claude Code가 생성한 코드에 대해 Claude Code 자체에게 "이 코드에서 문제가 될 수 있는 부분을 찾아줘"라고 교차 검증, pytest 코드도 Claude Code로 생성 후 학습자가 검토
   - **프롬프트 예시**: "이 코드를 리뷰하고 잠재적 문제점을 지적해줘", "이 서비스 함수에 대한 pytest 테스트를 작성해줘"
   - **커스텀 Skill 후보**: `/review` (지정 파일의 코드 리뷰 + 테스트 커버리지 확인 + 개선 제안)

10. **배포**
    - PyInstaller 빌드·배포
    - **SQLite → PostgreSQL 전환 실습** (ORM 덕분에 최소 변경)
    - **Claude Code 활용**: PyInstaller 빌드 설정, .spec 파일 생성, DB 전환 시 .env 수정과 Alembic 마이그레이션을 Claude Code가 수행
    - **프롬프트 예시**: "이 프로젝트를 PyInstaller로 빌드하기 위한 .spec 파일을 만들어줘", ".env를 PostgreSQL로 변경하고 마이그레이션을 실행해줘"
    - **커스텀 Skill 후보**: `/build` (의존성 확인 → PyInstaller 빌드 → 실행 테스트까지 자동화)

## 7. 제안에 포함해주세요

### 7.1 단원별 상세 (아래 항목 모두)
- 순서 · 단원명 · 학습목표(3개 이내)
- 주요 내용
- 실습 과제 (보일러플레이트의 어느 부분을 확장하는지 명시)
- **AI와 협업하는 방식** (이 단원에서 Claude Code에 무엇을 맡기고 무엇을 학습자가 하는가)
- **프롬프트 카탈로그**: 이 단원의 핵심 작업별로 Claude Code에서 사용하는 프롬프트 예시 (최소 2~3개). 학습자가 그대로 사용하거나 변형할 수 있는 수준으로 구체적으로 작성
- **커스텀 Skill 명세**: 이 단원에서 반복되는 작업 패턴이 있으면, 해당 패턴을 Claude Code 커스텀 Skill로 제작. Skill명, 용도, 입력/출력을 명시
- **자주 만나는 함정** 1~2개 (비개발자가 이 단원에서 흔히 막히는 지점 + 완화법)
- 예상 학습 시간
- **완료 기준** ("다음 단계로 넘어가도 되는" 판단 기준, 자가진단 체크리스트 형태)

### 7.2 캡스톤 프로젝트 (2개, 역할 구분 명확히)

**프로젝트 A: 가이드형 캡스톤** (커리큘럼 중반~후반 병행)
- 강사/커리큘럼이 요구사항·ERD·와이어프레임을 제공
- 학습자는 보일러플레이트 위에 **기능을 추가**하며 각 단원 개념을 체화
- 예시: 개인 할 일 관리 툴, 독서 기록 앱

**프로젝트 B: 자율형 캡스톤** (최종)
- 학습자가 **자기 업무의 실제 문제**를 주제로 선정
- PRD·ERD·와이어프레임부터 직접 작성 (AI와 협업)
- SQLite로 개발 → PostgreSQL 전환 → PyInstaller 배포까지 완주
- 예시: 간이 CRM, 거래처 관리, 회의록 아카이브 등

**두 프로젝트 모두 요건**:
- PyQt5 데스크톱 앱
- SQLAlchemy ORM 기반 데이터 영속성
- 보일러플레이트에서 출발
- 각 단원이 이 프로젝트의 어느 부분과 연결되는지 **매핑표** 제공
- **프롬프트 일지**: 캡스톤 개발 과정에서 Claude Code에 사용한 주요 프롬프트를 기록 (무엇을 요청했고, 결과가 어땠고, 어떻게 수정했는지)
- **커스텀 Skills 목록**: 프로젝트 중 제작·활용한 커스텀 Skill 목록과 각 Skill의 용도 정리

### 7.3 비개발자가 특히 막히기 쉬운 지점과 교수법
최소한 아래 4개는 별도 다루기:
- **가상환경 / 패키지 관리** (왜 필요한지 체감 안 됨)
- **PyQt5 이벤트 모델** (시그널/슬롯 추상화)
- **ORM 추상화** (객체인지 테이블인지 헷갈림)
- **에러 Traceback 읽기** (압도됨)

### 7.4 의도적으로 제외하는 주제와 이유
예: 비동기/멀티스레딩 고급, Qt MVC 프레임워크, PostgreSQL 튜닝, Docker, CI/CD, 클라우드 배포, 타입힌트 고급, 디자인 패턴 이론 — **스코프 관리를 위해 제외하는 이유를 각 항목별로 명시**

### 7.5 운영 설계
- 총 주차 / 1회차 분량 / 블렌디드 포맷 권장안
- 단원별 체크포인트와 캡스톤 평가 루브릭
- **학습자가 막혔을 때 복구 경로** (FAQ, Claude Code용 질문 프롬프트 템플릿, 조교 에스컬레이션 기준)

## 8. 출력 형식

1. **커리큘럼 개요**: 총 학습 시간, 최종 결과물, 페르소나 대비 달성 상태(Before/After)
2. **단원별 상세 표**: 순서 · 단원명 · 학습목표 · 주요 내용 · 실습 · **AI 협업 방식** · **프롬프트 카탈로그** · **커스텀 Skill 명세** · **자주 만나는 함정** · 예상 시간 · 완료 기준
3. **캡스톤 프로젝트 설계**:
   - 프로젝트 A·B 각각의 스펙
   - 아키텍처 다이어그램 (UI / Service / Repository / Model / DB 계층 분리)
   - 단원별 연결 매핑표
   - 평가 루브릭 (기능 완성도·아키텍처·검증 습관·문서화·**Claude Code 활용도** 각 영역별)
4. **프롬프트 & Skills 레퍼런스**: 커리큘럼 전체에서 사용되는 프롬프트 카탈로그와 커스텀 Skills 목록을 별도 부록으로 정리 (단원별 분류, Skill 정의 파일 포함)
5. **설계 근거 및 대안**: 원안 주제 순서/분량 대비 변경 사항, 그 이유, 운영 리스크 (이탈 포인트 등)
6. **권장 학습 자원**: 각 기술 스택별로 비개발자에게 적합한 1차 자료 2~3개 (한국어 우선, 없으면 영어)

## 9. 스타일 가이드

- 전체 설명은 **"왜 이걸 배우는지"**를 항상 먼저 제시
