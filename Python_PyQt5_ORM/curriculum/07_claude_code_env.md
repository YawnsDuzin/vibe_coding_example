# 단원 7: Claude Code 환경 — CLAUDE.md, Skills, 프롬프트 로깅

| 항목 | 내용 |
|------|------|
| **주차** | 7주 (13~14회차) |
| **예상 시간** | 6시간 (강의 2h + 실습 4h) |
| **보일러플레이트 연결** | `.claude/`, `CLAUDE.md` |

---

## 학습 목표 (3개)

1. CLAUDE.md의 역할을 이해하고, 프로젝트에 맞는 CLAUDE.md를 작성·관리할 수 있다
2. 자주 반복하는 작업 패턴을 Claude Code 커스텀 Skill로 제작할 수 있다
3. 프롬프트 로그를 분석하여 자신의 작업 패턴을 메타인지하고 개선할 수 있다

---

## 주요 내용

### 7.1 CLAUDE.md 작성법
- CLAUDE.md = "Claude Code에게 주는 프로젝트 브리핑 문서"
- 포함할 내용: 프로젝트 개요, 기술 스택, 디렉토리 구조, 코딩 컨벤션, 금지사항
- **의사결정 로그**: 왜 이 구조를 선택했는지 기록 → Claude Code가 맥락을 이해
- 보일러플레이트의 CLAUDE.md를 읽고 → 자기 프로젝트용으로 수정

### 7.2 커스텀 Skills 제작
- Skill = "자주 반복하는 프롬프트 패턴을 재사용 가능한 명령으로 만든 것"
- SKILL.md 구조: 용도, 실행 내용, 입력/출력
- 이전 단원에서 소개한 Skill 후보들을 실제로 제작·등록·테스트
  - `/generate-erd`, `/create-model`, `/create-form`, `/plan-feature`

### 7.3 프롬프트 자동 로깅 & Skill 추천 워크플로
- `UserPromptSubmit` hook의 동작 원리 이해
- `.claude/prompt-log.jsonl` 로그 파일 구조
- **실습**: 축적된 프롬프트 로그를 Claude Code에 전달하여:
  1. 반복 패턴 분석
  2. Skill 후보 추천
  3. 추천된 패턴을 실제 Skill로 제작

### 7.4 효과적인 프롬프트 구조화
- 맥락(Context) + 작업(Task) + 제약(Constraint) 구조
- "좋은 프롬프트"와 "나쁜 프롬프트"의 차이 비교
- 점진적 프롬프팅: 큰 작업을 여러 단계로 나누어 요청

## AI 협업 방식

| Claude Code가 하는 것 | 학습자가 하는 것 |
|----------------------|-----------------|
| CLAUDE.md 초안 생성 | 프로젝트 맥락에 맞게 검토·수정 |
| 프롬프트 로그 분석 → Skill 후보 추천 | 추천 결과를 평가하고 실제로 유용한 것 선별 |
| SKILL.md 초안 작성 | Skill의 입력/출력이 자기 워크플로에 맞는지 테스트 |

이 프로젝트에 맞는 CLAUDE.md를 생성해줘. 기술 스택, 디렉토리 구조, 코딩 컨벤션, 금지사항을 포함해줘.

```

```

## 커스텀 Skill 명세

### `/analyze-prompts`
| 항목 | 내용 |
|------|------|
| **용도** | 프롬프트 로그에서 반복 패턴 분석 → Skill 후보 추천 |
| **입력** | `.claude/prompt-log.jsonl` 파일 경로 |
| **출력** | 반복 패턴 목록 + 빈도수 + SKILL.md 초안 |
| **정의 위치** | `.claude/skills/analyze-prompts/SKILL.md` |

## 자주 만나는 함정

### 함정 1: "CLAUDE.md에 뭘 써야 할지 모르겠어요"
- **증상**: CLAUDE.md를 비워두거나 너무 일반적으로 작성
- **완화법**: 보일러플레이트의 CLAUDE.md를 템플릿으로 제공
  - "이 프로젝트에서만 특별한 것"을 적는 연습
  - 예: "DB는 반드시 ORM으로 접근", "UI에서 직접 DB 접근 금지"

### 함정 2: "Skill 만들었는데 안 돼요"
- **증상**: SKILL.md 문법 오류, 경로 오류
- **완화법**: 하나의 Skill을 처음부터 끝까지 같이 만들어보기
  - 정의 → 등록 → 테스트 → 수정 사이클 체험
