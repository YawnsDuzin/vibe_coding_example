# 단원 9: AI 산출물 검증 ★

| 항목 | 내용 |
|------|------|
| **주차** | 9주 (17~18회차) |
| **예상 시간** | 6시간 (강의 2h + 실습 4h) |
| **보일러플레이트 연결** | 캡스톤 A 검증·개선 |

---

## 학습 목표 (3개)

1. AI가 생성한 코드를 "읽고 의심하고 확인하는" 루틴을 습관화할 수 있다
2. pytest로 최소한의 테스트(2~3개)를 작성하고 실행할 수 있다
3. "AI가 모르는 것"을 알아차리는 신호들을 인지할 수 있다

---

## 주요 내용

### 9.1 AI 산출물 검증 루틴
1. **읽기**: 코드를 처음부터 끝까지 읽으며 "이 줄이 무슨 일을 하는지" 확인
2. **의심하기**: "이게 정말 맞나?" 질문
   - 엣지 케이스: 빈 입력, 중복 데이터, 최대값 초과
   - 계층 규칙: UI에서 직접 DB 접근하지 않았나?
   - 보안: 비밀번호 평문? SQL 인젝션 가능성?
3. **확인하기**: 직접 실행하여 기대대로 동작하는지 테스트

### 9.2 "AI가 모르는 것" 신호들
- **너무 자신만만할 때**: AI는 "잘 모르겠다"고 하지 않는 경향
- **기존 코드를 모를 때**: 프로젝트의 다른 부분과 충돌하는 코드 생성
- **환경/설정에 의존할 때**: 로컬 환경 차이를 반영하지 못함
- **최신 API를 모를 때**: 오래된 버전의 문법이나 폐기된 메서드 사용
- **교차 검증**: Claude Code에게 "이 코드에서 문제가 될 수 있는 부분을 찾아줘"

### 9.3 pytest 기초
- "코드가 제대로 동작하는지 자동으로 확인하는 도구"
- 최소 패턴 2개:
  1. **정상 케이스**: 올바른 입력 → 기대 결과
  2. **예외 케이스**: 잘못된 입력 → 올바른 에러 처리
- Claude Code로 테스트 코드 생성 → 학습자가 검토·실행

### 9.4 코드 리뷰 체크리스트
- [ ] 계층 분리 준수 여부
- [ ] 비밀번호 평문 저장 여부
- [ ] SQL 인젝션 가능성
- [ ] session.commit() 누락 여부
- [ ] 에러 처리 존재 여부
- [ ] 불필요한 import 또는 사용하지 않는 코드

## AI 협업 방식

| Claude Code가 하는 것 | 학습자가 하는 것 |
|----------------------|-----------------|
| 코드 리뷰 → 잠재적 문제점 지적 | 지적된 문제가 실제 문제인지 판단 |
| pytest 테스트 코드 생성 | 테스트가 올바른 것을 검증하는지 검토 |
| 교차 검증 ("이 코드의 문제점 찾아줘") | 여러 검증 결과를 종합하여 최종 판단 |

## 자주 만나는 함정

### 함정 1: "AI가 만들어줬으니 맞겠지"
- **증상**: AI 산출물을 검증 없이 그대로 사용
- **완화법**: 의도적으로 "AI가 틀린 코드"를 보여주고 찾게 하는 실습
  - 예: session.commit() 빠진 코드, SQL 인젝션 가능한 코드
  - "AI도 실수한다"는 체험을 여러 번 반복

### 함정 2: "테스트를 왜 해야 하는지 모르겠어요"
- **증상**: "실행해서 돌아가면 되는 거 아닌가요?"
- **완화법**: "지금은 되지만 나중에 다른 기능을 추가하면 깨질 수 있다"
  - 테스트 = "안전벨트" — 평소에는 귀찮지만 사고 시 생명을 구함
  - 2~3개만 작성해도 충분한 가치가 있다는 점 강조
