## 주요 내용

### 3.1 데이터 모델링 기초
- "현실 세계를 표(테이블)로 바꾸는 작업"
- 엔티티(Entity): 관리할 대상 (예: 사용자, 할 일, 거래처)
- 속성(Attribute): 각 대상의 특징 (예: 이름, 이메일, 생성일)
- 관계(Relationship): 대상 간의 연결 (예: 사용자 1명이 여러 할 일을 가짐)

### 3.2 ERD 읽기와 설계
- 1:N 관계: "한 명의 사용자가 여러 할 일을 가진다" (User → Tasks)
- N:M 관계: "한 명의 학생이 여러 강의를 수강하고, 한 강의에 여러 학생이 있다"
- PK(기본키), FK(외래키)의 역할
- **실습**: 보일러플레이트의 User-Role 관계를 ERD로 그리기

### 3.3 SQL 기초 개념
- DDL: 테이블을 만드는 명령 (CREATE TABLE)
- CRUD: 데이터를 넣고(INSERT), 읽고(SELECT), 바꾸고(UPDATE), 지우는(DELETE) 작업
- WHERE: 조건으로 필터링
- JOIN: 관련된 테이블을 연결하여 조회

### 3.4 SQLite 실습
- SQLite: "파일 하나가 곧 데이터베이스" — 설치 불필요
- Claude Code에서 SQLite 데이터 확인하기

## 프롬프트 카탈로그

### ERD 설계
```
"할 일 관리 앱"에 필요한 테이블을 설계해줘. 사용자는 여러 할 일을 가질 수 있고, 각 할 일은 카테고리에 속해. 이걸 Mermaid ERD 다이어그램으로 보여줘.
```

```
이 ERD에서 User와 Task의 관계가 1:N이 맞는지 확인해줘. 한 Task가 여러 User에게 할당될 수도 있으면 어떻게 바뀌어야 하는지도 설명해줘.
```

### SQL 생성 및 학습
```
이 ERD를 SQLite CREATE TABLE 문으로 변환해줘. 각 컬럼에 대해 왜 이 데이터 타입을 선택했는지 주석으로 설명해줘.
```

```
users 테이블에 예시 데이터 3개를 INSERT하고, role이 'admin'인 사용자만 조회하는 SELECT 쿼리를 보여줘.
```

## 자주 만나는 함정

### 함정 1: "테이블이 엑셀 시트랑 뭐가 달라요?"
- **증상**: 관계형 DB의 "관계" 개념을 놓침, 모든 데이터를 하나의 테이블에 넣으려 함
- **완화법**: 엑셀에서 시트 간 VLOOKUP을 쓰는 이유와 연결
  - "별도 시트에 역할 목록을 만들고 VLOOKUP으로 참조하는 것 = 별도 테이블 + FK"
  - 데이터 중복의 문제점을 엑셀 예시로 시연

### 함정 2: "N:M 관계가 이해 안 돼요"
- **증상**: 중간 테이블(연결 테이블)의 필요성을 직감하지 못함
- **완화법**: 수강신청 예시로 체감
  - "학생 테이블에 수업을 쓰면? 여러 수업을 듣는 학생은 어떻게?"
  - 중간 테이블 = "출석부"라는 비유
