# 단원 8: AI와 함께하는 개발·디버깅

| 항목 | 내용 |
|------|------|
| **주차** | 8주 (15~16회차) |
| **예상 시간** | 6시간 (강의 2h + 실습 4h) |
| **보일러플레이트 연결** | 캡스톤 A 구현 시작 |

---

## 학습 목표 (3개)

1. 효과적인 프롬프팅 전략(맥락 제공, 제약 명시, 검증 요청)을 적용할 수 있다
2. Python Traceback을 읽고 에러의 위치와 원인을 파악할 수 있다
3. 재현 가능한 버그 리포트를 작성하고, Claude Code와 체계적으로 디버깅할 수 있다

---

## 주요 내용

### 8.1 프롬프팅 전략
- **맥락 제공**: "지금 어떤 상태인지" 알려주기
  - 나쁜 예: "할 일 기능 만들어줘"
  - 좋은 예: "Task 모델이 이미 있고, TaskRepository의 CRUD가 완성된 상태야. 이제 TaskService에 완료 상태 변경 로직을 추가해줘"
- **제약 명시**: "하지 말아야 할 것" 명확히
  - "기존 코드 구조를 바꾸지 마", "Service 계층에서만 수정해"
- **검증 요청**: "확인해줘" 명시적으로 요청
  - "이 코드에서 session.commit()이 빠진 곳이 있는지 확인해줘"

### 8.2 에러 메시지 읽는 법 (Traceback 해부)
- Traceback = "에러가 발생한 경로 안내서"
- **아래에서 위로 읽기**: 마지막 줄이 에러 종류, 위로 갈수록 호출 경로
- 핵심 정보 3가지: ① 에러 종류, ② 에러 메시지, ③ 발생 위치(파일:줄번호)
- 흔한 에러들:
  - `NameError`: 존재하지 않는 변수/함수 사용
  - `TypeError`: 잘못된 타입의 인자 전달
  - `AttributeError`: 객체에 없는 속성/메서드 접근
  - `IntegrityError`: DB 제약조건 위반 (중복, NULL 등)

### 8.3 재현 가능한 버그 리포트
- 좋은 버그 리포트의 구성:
  1. **무엇을 했는가** (재현 단계)
  2. **무엇을 기대했는가** (기대 결과)
  3. **실제로 무엇이 발생했는가** (실제 결과 + Traceback)
- Claude Code에 버그를 전달할 때도 이 구조로 전달

### 8.4 GUI 특유의 디버깅
- 이벤트 루프 관련: 무한 루프, 화면 멈춤
- DB 락: 여러 곳에서 동시에 DB 접근
- 위젯 생명주기: 닫힌 위젯에 접근

## AI 협업 방식

| Claude Code가 하는 것 | 학습자가 하는 것 |
|----------------------|-----------------|
| Traceback 분석 → 원인 진단 | Traceback에서 에러 종류와 위치를 먼저 읽어보기 |
| 수정 코드 제안 | 수정이 합리적인지 검토, 실행하여 확인 |
| 재현 조건 정리 도움 | 버그가 발생한 상황을 구체적으로 기록 |

---

## 프롬프트 카탈로그

```
이 에러 Traceback을 분석해줘. 에러 종류, 발생 위치, 원인, 수정 방법을 단계별로 설명해줘:
[Traceback 내용 붙여넣기]
```

```
저장 버튼을 클릭하면 아무 반응이 없어. 에러도 안 나. 가능한 원인들을 나열하고, 각각을 확인하는 방법을 알려줘.
```

```
이 버그의 재현 조건을 정리해줘: [현상 설명]. 재현 단계, 기대 결과, 실제 결과 형식으로 정리해줘.
```

## 자주 만나는 함정

### 함정 1: "에러 메시지가 무서워요 (Traceback 공포)"
- **증상**: 빨간 글씨와 긴 Traceback에 압도됨
- **완화법**: "아래에서 위로 3줄만 읽으세요" 규칙
  - 마지막 줄: 에러 종류와 메시지 (가장 중요!)
  - 그 위 줄: 에러가 발생한 파일과 줄 번호
  - 그 위 줄: 어떤 코드에서 발생했는지
  - 나머지는 "경로"이므로 무시해도 됨

### 함정 2: "안 돼, 고쳐줘"
- **증상**: 에러 내용을 확인하지 않고 바로 Claude Code에 "고쳐줘"
- **완화법**: 최소한 에러 종류와 메시지를 함께 전달하도록 훈련
  - 나쁜 프롬프트: "에러 나, 고쳐줘"
  - 좋은 프롬프트: "IntegrityError: UNIQUE constraint failed: users.username 에러가 나. 중복 사용자명 처리를 추가해줘"
