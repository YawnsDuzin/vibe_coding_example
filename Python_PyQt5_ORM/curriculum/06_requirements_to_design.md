# 단원 6: 요구사항 → 바이브코딩 가능한 설계

| 항목 | 내용 |
|------|------|
| **주차** | 6주 (11~12회차) |
| **예상 시간** | 6시간 (강의 2h + 실습 4h) |
| **보일러플레이트 연결** | 캡스톤 A 설계 시작, 전체 구조 |

---

## 학습 목표 (3개)

1. 업무 요구사항을 PRD(제품 요구사항 문서)로 구조화할 수 있다
2. PRD에서 ERD, UI 와이어프레임, 아키텍처 계층을 도출할 수 있다
3. 큰 기능을 바이브코딩 가능한 작은 작업(To-do)으로 분해할 수 있다

---

## 주요 내용

### 6.1 PRD 작성법
- PRD = "무엇을 왜 만드는가"를 정리한 문서
- 구성: 배경/목표, 사용자 스토리, 기능 목록, 비기능 요구사항
- **Claude Code로 작성**: 자연어 설명 → PRD 초안 → 학습자 검토·수정

### 6.2 ERD 설계 (복습 + 심화)
- PRD에서 엔티티·속성·관계 도출
- 단원 3에서 배운 내용을 실제 프로젝트에 적용

### 6.3 UI 와이어프레임
- 종이 스케치 또는 간단한 도구로 화면 배치
- "어떤 데이터가 어떤 화면에서 필요한가?"
- UI ↔ ERD 교차 검증

### 6.4 아키텍처 결정
- UI → Service → Repository → Model 계층 분리
- 각 기능을 어느 계층에 배치할지 결정
- "로그인 버튼 클릭부터 DB 조회까지의 여정"

### 6.5 작업 분해 (To-do 리스트)
- 큰 기능 → 계층별 작은 작업으로 분해
- 각 작업이 "하나의 Claude Code 프롬프트로 처리 가능한 크기"가 되도록
- 작업 순서와 의존성 결정

---

## AI 협업 방식

| Claude Code가 하는 것 | 학습자가 하는 것 |
|----------------------|-----------------|
| PRD 초안 작성 | 요구사항이 빠짐없이 반영되었는지 검토·수정 |
| ERD 다이어그램 생성 | 관계가 올바른지, 빠진 엔티티가 없는지 판단 |
| 계층별 To-do 분해 | 작업 순서와 우선순위 결정 |

---

## 프롬프트 카탈로그

```
"개인 할 일 관리 앱"의 PRD를 작성해줘. 기능 목록, 사용자 스토리, 비기능 요구사항을 포함해줘.
```

```
이 PRD를 기반으로 ERD를 설계해줘. Mermaid 다이어그램으로 보여주고, 각 테이블의 역할을 설명해줘.
```

```
이 PRD와 ERD를 기반으로 UI/Service/Repository/Model 계층으로 작업을 분해해줘. 각 작업은 Claude Code에서 한 번에 처리할 수 있는 크기로 나눠줘.
```

## 자주 만나는 함정

### 함정 1: "뭘 만들지 막연해요"
- **증상**: 요구사항 자체를 정리하지 못하고 바로 코드를 요청
- **완화법**: "1주일 동안 엑셀로 관리하던 업무"를 떠올리게 함
  - 구체적 질문: "매일 반복하는 작업 중 가장 귀찮은 것은?"
  - "그 엑셀에 어떤 시트/컬럼이 있는지"부터 시작

### 함정 2: "To-do가 너무 크거나 너무 작아요"
- **증상**: "로그인 기능 만들기" (너무 큼) 또는 "변수 이름 짓기" (너무 작음)
- **완화법**: 기준 제시 — "Claude Code에 하나의 프롬프트로 지시할 수 있는 크기"
  - 좋은 예: "Task 모델에 CRUD Repository를 만들어줘"
  - 나쁜 예: "앱을 만들어줘" / "변수명을 바꿔줘"
