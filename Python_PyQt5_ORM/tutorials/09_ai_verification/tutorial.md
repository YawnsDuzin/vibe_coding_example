# 튜토리얼 9: AI 산출물 검증

> **이 단원에서 배우는 것**: AI가 생성한 코드를 "읽고 의심하고 확인하는" 습관을 만듭니다.
> 코드 리뷰 체크리스트와 pytest 기초를 익힙니다.

---

## 왜 이걸 배우나요?

AI(Claude Code)는 매우 유능하지만, **항상 정확한 것은 아닙니다.**
"AI가 만들어줬으니 맞겠지"라고 생각하면 위험합니다.

비유: 숙련된 비서가 작성한 보고서도 결재 전에 꼭 검토하는 것처럼,
AI가 생성한 코드도 반드시 **읽고 → 의심하고 → 확인**해야 합니다.

---

## 실습 1: AI가 틀린 코드 찾기

### Claude Code에 입력해보세요

```
아래 코드에 의도적으로 숨긴 버그 3개를 찾아줘:

def create_user(username, password, email):
    session = get_session()
    user = User(
        username=username,
        email=email,
        password_hash=password  # 여기가 맞나요?
    )
    session.add(user)
    # session.commit()이 여기 있어야 할까요?
    return user
```

### 찾아야 할 버그들

1. **비밀번호 평문 저장**: `password_hash=password` → `password_hash=hash_password(password)` 필요
2. **session.commit() 누락**: 데이터가 DB에 실제로 저장되지 않음
3. **session.close() 누락**: DB 연결 자원 누수

### 검증 포인트 ✓
- [ ] 비밀번호 평문 저장이 왜 위험한지 설명할 수 있나요?
- [ ] session.commit() 없이도 에러가 안 나는 이유를 이해하나요? (답: 에러는 안 나지만 DB에 저장 안 됨)

## 실습 2: 코드 리뷰 체크리스트 실행

### 체크리스트

캡스톤 A 프로젝트의 코드를 다음 체크리스트로 검토합니다:

- [ ] **계층 분리**: UI 코드에서 직접 DB 접근(session, query)이 없는가?
- [ ] **비밀번호**: 평문 저장 없이 hash_password() 사용하는가?
- [ ] **SQL 안전**: 문자열 결합 대신 ORM 쿼리 또는 바인딩 변수 사용하는가?
- [ ] **session**: commit(), rollback(), close()가 적절히 있는가?
- [ ] **에러 처리**: try/except가 적절한 곳에 있는가?
- [ ] **import**: 사용하지 않는 import가 없는가?

### Claude Code에 입력해보세요

```
캡스톤 A 프로젝트에서 변경한 파일들을 리뷰해줘.
위의 코드 리뷰 체크리스트를 기준으로 각 항목을 확인하고 결과를 알려줘.
```

## 실습 3: pytest로 최소 테스트 작성

### 왜 테스트를 쓰나요?
테스트 = "안전벨트"입니다. 평소에는 귀찮지만, 문제가 생겼을 때 생명을 구합니다.
"지금은 잘 돌아가지만, 나중에 기능을 추가하면 기존 기능이 깨질 수 있다"를 방지합니다.

### Claude Code에 입력해보세요

```
app/services/auth_service.py의 register 메서드에 대한 pytest 테스트를 작성해줘.

1. 정상 케이스: 올바른 정보로 회원가입 성공
2. 예외 케이스: 중복 사용자명으로 가입 시 에러 발생
3. 예외 케이스: 비밀번호가 빈 문자열일 때 처리

파일 위치: tests/test_auth_service.py
각 테스트에 한국어 주석으로 "무엇을 테스트하는지" 설명해줘.
```

### 테스트 실행

```
pytest 테스트를 실행해줘. 결과를 보여주고, 실패한 테스트가 있으면 원인을 설명해줘.
```

### 검증 포인트 ✓
- [ ] `assert` 구문이 "기대 결과와 실제 결과를 비교한다"는 것을 이해하나요?
- [ ] 테스트 함수 이름이 `test_`로 시작해야 하는 이유를 알고 있나요? (pytest가 인식하기 위해)

## 실습 4: "AI가 모르는 것" 알아차리기

### 주요 신호들

1. **너무 자신만만할 때**: AI가 "확실히 이렇게 하면 됩니다"라고 하면, 한 번 더 검증
2. **기존 코드를 모를 때**: 프로젝트의 다른 파일과 이름이 충돌하거나 패턴이 다른 코드 생성
3. **환경 차이를 무시할 때**: "이 경로에 파일이 있습니다"라고 하는데 실제로 없을 때

### Claude Code에 입력해보세요

```
방금 생성한 코드에서 보일러플레이트의 기존 구조와 충돌하는 부분이 있는지 확인해줘.
특히:
1. 계층 구조(UI/Service/Repository/Model)를 따르는지
2. 기존 코드의 네이밍 규칙과 일치하는지
3. 이미 존재하는 유틸리티를 중복 구현하지 않았는지
```

## 이 단원을 마치며

이제 여러분은:
- AI가 생성한 코드를 무조건 신뢰하지 않고 검증하는 습관을 가집니다
- 코드 리뷰 체크리스트를 사용하여 주요 문제를 발견할 수 있습니다
- pytest로 최소한의 테스트를 작성하고 실행할 수 있습니다
- "AI가 모르는 것"의 신호를 인지할 수 있습니다

**기억하세요**: AI를 활용하되, 최종 판단은 항상 사람이 합니다.
