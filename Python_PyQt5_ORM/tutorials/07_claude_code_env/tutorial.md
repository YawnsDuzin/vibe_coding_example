# 튜토리얼 7: Claude Code 환경 — CLAUDE.md, Skills, 프롬프트 로깅

> **이 단원에서 배우는 것**: Claude Code를 "나만의 개발 파트너"로 만드는 방법을 배웁니다.
> CLAUDE.md로 프로젝트 맥락을 전달하고, 커스텀 Skills로 반복 작업을 자동화하고,
> 프롬프트 로깅으로 자신의 작업 패턴을 분석합니다.

---

## 시작하기 전에

지금까지 우리는 Claude Code에게 매번 처음부터 설명했습니다.
"이 프로젝트는 PyQt5로 만든 앱이고, 계층 구조는 이렇고..."

비유하자면, 매번 새로운 비서에게 회사 소개부터 하는 것과 같습니다.
이 단원에서는 Claude Code에게 **"우리 회사 매뉴얼"**을 주는 방법을 배웁니다.
매뉴얼을 한 번 주면, 이후로는 매번 설명하지 않아도 됩니다.

---

## 실습 1: CLAUDE.md — "프로젝트 매뉴얼" 만들기

### 왜 이걸 배우나요?
`CLAUDE.md`는 Claude Code가 프로젝트에서 작업할 때 **항상 참고하는 문서**입니다.
여기에 프로젝트의 규칙, 기술 스택, 금지사항을 적어두면
Claude Code가 **맥락을 이해한 상태로** 코드를 생성합니다.

CLAUDE.md가 없으면:
- Claude Code가 프로젝트 규칙을 모르고 코드를 생성합니다
- UI에서 직접 DB에 접근하는 코드를 만들 수 있습니다
- `.env`에 넣어야 할 정보를 코드에 하드코딩할 수 있습니다

### Claude Code에 입력해보세요

#### 1-1. 기존 CLAUDE.md 분석

```
보일러플레이트의 CLAUDE.md를 읽고, 어떤 내용이 들어있는지 항목별로 정리해줘.
각 항목이 왜 필요한지 설명해줘.
```

#### 1-2. 나만의 CLAUDE.md 작성

```
내가 "독서 기록 앱" 프로젝트를 만든다고 가정하고,
보일러플레이트의 CLAUDE.md를 참고하여 새 CLAUDE.md를 작성해줘.

포함할 내용:
1. 프로젝트 개요 (무엇을 만드는지)
2. 기술 스택 (Python, PyQt5, SQLAlchemy, SQLite)
3. 디렉토리 구조 (보일러플레이트 기반)
4. 코딩 컨벤션 (계층 분리, 한국어 주석 등)
5. 금지사항 (UI에서 직접 DB 접근 금지 등)
6. 의사결정 로그 (왜 이렇게 설계했는지 기록)
```

### CLAUDE.md에 꼭 넣어야 할 것들

| 항목 | 왜 필요한가 | 예시 |
|------|-------------|------|
| 프로젝트 개요 | Claude Code가 맥락을 파악 | "개인 독서 기록 관리 앱" |
| 기술 스택 | 다른 기술을 제안하지 않도록 | "PyQt5, SQLAlchemy, SQLite" |
| 코딩 컨벤션 | 일관된 코드 스타일 유지 | "모든 주석은 한국어" |
| 금지사항 | 실수를 사전에 방지 | "print() 디버깅 금지, logger 사용" |
| 계층 규칙 | 아키텍처 준수 | "UI → Service → Repository → Model" |

### 검증 포인트 ✓
- [ ] CLAUDE.md가 없을 때와 있을 때 Claude Code의 응답이 어떻게 달라지는지 이해하나요?
- [ ] 자기 프로젝트에 맞는 금지사항을 3개 이상 생각해낼 수 있나요?

## 실습 2: 커스텀 Skills — "자주 쓰는 명령을 버튼 하나로"

### 왜 이걸 배우나요?
커스텀 Skill은 **자주 반복하는 작업 패턴을 하나의 명령으로 묶어둔 것**입니다.

비유하자면, 요리할 때 매번 "양파를 깍둑썰기하고, 기름을 두르고, 중불에서 볶고..."라고
하나하나 설명하는 대신, "양파 볶기 레시피"라는 이름을 붙여두는 것과 같습니다.
다음번에는 "양파 볶기 레시피대로 해줘"라고만 하면 됩니다.

### Claude Code에 입력해보세요

#### 2-1. 기본 Skill 사용해보기

```
보일러플레이트에 미리 설정된 커스텀 Skills 목록을 보여주고,
각 Skill이 무엇을 하는지 설명해줘.
```

#### 2-2. 나만의 Skill 만들기 — `/explain-code`

```
다음 기능을 하는 커스텀 Skill을 만들어줘:

Skill 이름: /explain-code
용도: 지정한 파일의 코드를 비개발자 눈높이로 한 줄씩 해설
입력: 파일 경로
출력: 코드 블록마다 한국어 설명 (비유 포함)

.claude/skills/explain-code/SKILL.md 파일로 만들어줘.
```

#### 2-3. Skill 테스트

```
방금 만든 /explain-code Skill을 사용해서
app/services/auth_service.py를 설명해줘.
```

### Skill 정의 파일 구조

Skill 파일(`.claude/skills/<이름>/SKILL.md`)에 들어가는 내용:

```markdown
# /explain-code

## 용도
지정한 파일의 코드를 비개발자가 이해할 수 있도록 해설합니다.

## 입력
- 파일 경로 (예: app/services/auth_service.py)

## 출력
- 코드 블록별 한국어 설명
- 핵심 로직에 대한 비유 설명
- 이 코드가 전체 앱에서 하는 역할 요약

## 규칙
- 전문 용어 사용 시 반드시 쉬운 말로 풀어서 설명
- "입력 → 처리 → 출력" 구조로 정리
- 보일러플레이트의 계층 구조 기준으로 역할 설명
```

### 검증 포인트 ✓
- [ ] 커스텀 Skill의 용도를 자기 말로 설명할 수 있나요?
- [ ] "내 작업에서 반복되는 패턴"을 하나 이상 생각해낼 수 있나요?

## 실습 3: 프롬프트 로깅 — "내가 뭘 물어봤는지 기록하기"

### 왜 이걸 배우나요?
프롬프트 로깅은 **Claude Code에게 했던 모든 질문/요청을 자동으로 기록**하는 것입니다.

왜 이게 중요할까요?
1. **학습 일지**가 됩니다 — "나는 어떤 것을 많이 물어보는구나"를 알 수 있습니다
2. **반복 패턴 발견** — 같은 유형의 질문을 자주 한다면, Skill로 만들 수 있습니다
3. **프롬프트 개선** — 과거의 질문을 보면서 "더 좋은 질문법"을 익힐 수 있습니다

비유하자면, 요리를 배울 때 "오늘 뭘 만들었고 어떤 실수를 했는지" 적는 **요리 일지**와 같습니다.

### Claude Code에 입력해보세요

#### 3-1. 프롬프트 로깅 구조 이해

```
보일러플레이트에 설정된 프롬프트 로깅 hook을 설명해줘.
.claude/settings.json의 hook 설정과
.claude/hooks/log-prompts.sh 파일이 어떻게 작동하는지 알려줘.

특히:
- 프롬프트가 어디에 저장되는지 (.claude/prompt-log.jsonl)
- 왜 .gitignore에 추가하는지 (민감 정보 보호)
- JSONL 파일 형식이 무엇인지
```

#### 3-2. 프롬프트 로그 확인

```
.claude/prompt-log.jsonl 파일이 있으면 내용을 보여주고,
지금까지 내가 어떤 유형의 질문을 많이 했는지 분석해줘.

카테고리별로 분류해줘:
- 코드 설명 요청
- 코드 생성 요청
- 디버깅 요청
- 설계/기획 관련
- 기타
```

### 검증 포인트 ✓
- [ ] 프롬프트 로그가 어디에 저장되는지 알고 있나요?
- [ ] 왜 프롬프트 로그를 Git에 올리면 안 되는지 설명할 수 있나요?
- [ ] hook이 "특정 이벤트가 발생하면 자동으로 실행되는 스크립트"라는 것을 이해하나요?

## 실습 4: 프롬프트 패턴 분석 → Skill 추천 받기

### 왜 이걸 배우나요?
프롬프트 로그를 분석하면 **"내가 반복적으로 하는 작업"**을 발견할 수 있습니다.
반복되는 작업은 커스텀 Skill로 만들면 매번 같은 긴 프롬프트를 쓰지 않아도 됩니다.

이 과정은 단순한 편의성을 넘어서,
**자신의 작업 패턴을 객관적으로 바라보는 메타인지 훈련**이기도 합니다.

### Claude Code에 입력해보세요

#### 4-1. 패턴 분석

```
.claude/prompt-log.jsonl의 프롬프트들을 분석해서:
1. 가장 자주 반복되는 작업 패턴 3개를 찾아줘
2. 각 패턴이 몇 번 나타났는지
3. 이 패턴을 Skill로 만들면 어떤 이점이 있는지
4. 추천 Skill 이름과 간략한 설명

표 형태로 정리해줘.
```

#### 4-2. 추천받은 Skill 제작

```
위에서 추천받은 Skill 중 가장 유용해 보이는 것 1개를
실제 SKILL.md 파일로 만들어줘.
.claude/skills/ 디렉토리에 저장해줘.
```

### `/analyze-prompts` Skill 만들기

이 "프롬프트 분석 → Skill 추천" 작업 자체도 반복되므로, Skill로 만들 수 있습니다:

```
다음 기능을 하는 커스텀 Skill을 만들어줘:

Skill 이름: /analyze-prompts
용도: .claude/prompt-log.jsonl에서 반복 패턴 분석 → Skill 후보 추천
입력: 없음 (자동으로 로그 파일 읽기)
출력: 반복 패턴 목록 + 추천 Skill 이름·설명 + SKILL.md 초안

.claude/skills/analyze-prompts/SKILL.md 파일로 만들어줘.
```

### 검증 포인트 ✓
- [ ] 프롬프트 로그에서 반복 패턴을 찾는 과정을 이해하나요?
- [ ] "반복되는 패턴 → Skill 제작"의 흐름을 설명할 수 있나요?
- [ ] 자기 작업에서 Skill로 만들 만한 반복 패턴을 하나 이상 생각해낼 수 있나요?

## 이 단원에서 다룬 Claude Code 설정 요약

```
.claude/
├── settings.json              # hook 설정 (프롬프트 로깅 등)
├── hooks/
│   └── log-prompts.sh         # 프롬프트 로깅 스크립트
├── prompt-log.jsonl           # 프롬프트 로그 (gitignore 대상)
└── skills/                    # 커스텀 Skill 정의
    ├── explain-code/
    │   └── SKILL.md
    ├── plan-feature/
    │   └── SKILL.md
    └── analyze-prompts/
        └── SKILL.md
```

## 이 단원을 마치며

축하합니다! 이제 여러분은:
- **CLAUDE.md**로 Claude Code에게 프로젝트 맥락을 전달할 수 있습니다
- **커스텀 Skills**로 반복 작업을 하나의 명령으로 줄일 수 있습니다
- **프롬프트 로깅**으로 자신의 작업 패턴을 기록하고 분석할 수 있습니다
- 분석 결과를 바탕으로 **새로운 Skill을 제작**할 수 있습니다

이것은 단순한 도구 설정이 아닙니다.
CLAUDE.md를 잘 쓰는 것은 **"내 프로젝트를 명확하게 설명하는 능력"**이고,
Skill을 만드는 것은 **"내 작업의 반복 패턴을 인식하는 능력"**입니다.
이 두 가지 능력은 AI 도구를 넘어서, 어떤 일을 하든 도움이 되는 메타 역량입니다.

다음 단원에서는 **AI와 함께 디버깅하는 방법**을 배웁니다.
에러가 발생했을 때 당황하지 않고 원인을 찾는 전략을 익힙니다.
