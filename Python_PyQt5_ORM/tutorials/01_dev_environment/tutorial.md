# 튜토리얼 1: 개발 환경과 기초 IT 지식

> **이 단원에서 배우는 것**: 프로젝트를 시작하기 위한 기본 환경을 설정합니다.
> 터미널, 파일 구조, Git, 가상환경의 개념을 Claude Code와 함께 익힙니다.

---

## 시작하기 전에

이 튜토리얼을 시작하려면 다음이 필요합니다:
- VSCode가 설치되어 있어야 합니다
- Claude Code Extension이 설치되어 있어야 합니다
- 보일러플레이트 프로젝트를 다운로드했어야 합니다

---

## 실습 1: 프로젝트 구조 탐색하기

### 왜 이걸 배우나요?
프로젝트의 파일 구조를 이해해야 "어디에 무엇이 있는지" 알 수 있습니다.
마치 건물에 처음 들어가면 안내도를 보는 것처럼요.

### Claude Code에 입력해보세요

```
현재 프로젝트의 파일 구조를 트리 형태로 보여주고,
각 디렉토리가 무슨 역할인지 한 줄씩 설명해줘
```

### 기대 결과
Claude Code가 다음과 비슷한 구조를 보여줄 것입니다:

```
boilerplate/
├── app/
│   ├── ui/           → 화면에 보이는 것들 (버튼, 입력칸, 메뉴 등)
│   ├── services/     → 비즈니스 로직 (판단하는 곳)
│   ├── repositories/ → 데이터를 읽고 쓰는 곳
│   ├── models/       → 데이터 구조 정의 (테이블 설계도)
│   ├── core/         → 앱의 기반 설정 (로깅, 인증, DB 연결)
│   └── resources/    → 디자인 파일 (스타일, 아이콘)
```

### 검증 포인트 ✓
- [ ] 각 디렉토리의 역할을 자기 말로 설명할 수 있나요?
- [ ] "services 디렉토리에 뭐가 들어가나요?"라는 질문에 답할 수 있나요?

## 실습 2: 가상환경 만들기

### 왜 이걸 배우나요?
가상환경은 "이 프로젝트만을 위한 전용 도구 상자"입니다.
프로젝트마다 필요한 도구(패키지)의 버전이 다를 수 있기 때문입니다.

비유: 요리사가 한식/양식/중식 요리를 할 때, 각각 다른 양념 세트를 쓰는 것과 같습니다.
한 양념통에 다 섞으면 맛이 이상해지듯, 패키지도 섞이면 충돌이 납니다.

### Claude Code에 입력해보세요

```
venv를 만들고 requirements.txt에서 패키지를 설치해줘.
각 단계가 무엇을 하는지 설명도 해줘.
```

### 설치 후 확인

```
설치된 패키지 목록을 보여주고, 각 패키지가 우리 프로젝트에서 어떤 역할을 하는지 간단히 설명해줘
```

### 검증 포인트 ✓
- [ ] "왜 가상환경이 필요한지" 동료에게 설명할 수 있나요?
- [ ] `requirements.txt`가 무엇인지 알고 있나요? (답: 패키지 목록표)

## 실습 3: .env 파일 이해하기

### 왜 이걸 배우나요?
비밀번호, DB 접속 정보 같은 민감한 정보는 코드에 직접 쓰면 안 됩니다.
`.env` 파일에 따로 보관하고, `.gitignore`로 Git에 올라가지 않게 합니다.

### Claude Code에 입력해보세요

```
.env.example을 복사해서 .env 파일을 만들어줘.
각 설정값이 무엇을 의미하는지 설명해줘.
특히 DB_TYPE, SQLITE_DB_PATH, LOG_LEVEL이 중요하니 자세히 설명해줘.
```

### 검증 포인트 ✓
- [ ] `.env` 파일이 왜 Git에 올라가면 안 되는지 설명할 수 있나요?
- [ ] `DB_TYPE=sqlite`와 `DB_TYPE=postgresql`의 차이를 이해하나요?

## 실습 4: Git 기초 — 저장 지점 만들기

### 왜 이걸 배우나요?
Git은 "코드의 저장 지점(세이브 포인트)"을 만드는 도구입니다.
게임에서 세이브 포인트를 찍어두면 망해도 돌아갈 수 있듯이,
Git 커밋을 해두면 코드가 망가져도 이전 상태로 돌아갈 수 있습니다.

### Claude Code에 입력해보세요

#### 4-1. 현재 상태 확인
```
지금 프로젝트의 Git 상태를 확인해줘. 변경된 파일이 있는지 보여줘.
```

#### 4-2. 첫 번째 커밋
```
지금까지의 변경사항을 "프로젝트 초기 환경 설정 완료"라는 메시지로 커밋해줘
```

#### 4-3. 커밋 히스토리 확인
```
Git 커밋 히스토리를 보여주고, 각 커밋이 무엇을 했는지 요약해줘
```

### 검증 포인트 ✓
- [ ] "커밋"이 무엇인지 자기 말로 설명할 수 있나요? (답: 저장 지점)
- [ ] 왜 자주 커밋하는 것이 좋은지 이해하나요?
